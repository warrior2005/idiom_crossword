# 成语填字游戏 — 科举仕途成长系统设计

> 设计文档 | 2026-07-04 | v1.0

---

## 一、设计概述

### 1.1 目标

将成语填字游戏从"纯关卡挑战"升级为"成长驱动型"产品，通过科举仕途主题的等级体系、螺旋难度递增和道具系统，为玩家提供长期游玩目标。

### 1.2 核心设计原则

- **成长感**：21 级（含 Lv.∞ 真龙天子）指数经验曲线，前期快速晋升，后期长线留存
- **自然过渡**：螺旋难度模型，成语 1-50 难度粒度，避免难度断层
- **收藏价值**：所有已完成成语自动收录，附带释义出处
- **广告变现与积分平衡**：功能道具+装饰道具均以积分兑换，不影响游戏难度和成语选择

### 2.2 经验公式

```
XP(n) = 100 × 1.6^(n-1)
```

最高等级为 **Lv.∞ 真龙天子**（内部记为 21 级）：Lv.20 位极人臣后，再累计 7,430,474 经验到达，约对应主线第 20000 关。

- 第 1 级→第 2 级：100 经验（约第 15 关）
- 第 5 级→第 6 级：655 经验（约第 185 关）
- 第 10 级→第 11 级：6,872 经验（约第 628 关）
- 第 15 级→第 16 级：72,058 经验（约第 2,260 关）
- 第 19 级→第 20 级：472,237 经验（约第 7,550 关）
- 第 20 级→Lv.∞：7,430,474 经验（约第 20,000 关）

### 2.3 经验获取

- 每通关一关获得经验 = 5 + floor((关卡编号 − 1) × 43 / 1000)（6 关起）
- 教学关（1-5关）经验固定为 20
- 每日挑战固定 300 经验，不随每日关卡号膨胀
- 不做每日挑战时约 7500 关升到 20 级；按约 1000 次每日挑战估算，可提前到约 6600 关
- 达到 Lv.20 后，主线关卡使用「波浪中心 + 三区混排」：难度中心在 20～40 间随关卡号缓慢波动，主体/回顾/冲刺/惊喜四区混排（详见 §4.6）
- 无其他经验来源（纯通关驱动）

## 三、关卡结构

### 3.1 关卡总量

- **总关卡**：无限生成（10,000+ 关起步）
- **教学关**（1-5关），纯难度 1：
  - 第 1 关：主体 5
  - 第 2 关：主体 6
  - 第 3-4 关：主体 7
  - 第 5 关：主体 8
- **正式关**（6关起）按玩家等级分段：
  - Lv.5 前：主体 8 + 长尾 0-1 + 预览 0-1，共 8-10 条
  - Lv.5 起、Lv.10 前：主体 8 + 长尾 0-1 + 预览 1-2，共 9-11 条
  - Lv.10 起、Lv.20 前：主体 7 + 长尾 1-2 + 预览 3，共 11-12 条
  - Lv.20 后：主体 8 + 回顾 0 + 冲刺 2-3 + 惊喜 0-1，共 10-12 条
- **每日挑战**：固定 12 条，难度下限 10，且比当前 Lv 主体难度大 5

### 3.2 成语池

- **总量**：29,502 条四字成语（已评分 1-50）
- **保底规则**：每条成语至少出现 3 次
- **复用策略**：全局池随机抽取，按难度权重选择

### 3.3 难度映射

```
关卡基准难度 = ceil(关卡编号 / 200)  （线性映射到 1-50）
```

| 关卡区间 | 基准难度 | 主体难度范围 |
|----------|----------|--------------|
| 1-200 | 1 | 1-4 |
| 201-400 | 2 | 1-5 |
| 401-600 | 3 | 1-6 |
| ... | ... | ... |
| 9801-10000 | 50 | 45-50 |

## 四、螺旋难度模型

### 4.1 核心理念

难度递增采用"螺旋上升"模式，而非严格隔离：
- 每关以当前难度区间的成语为主体（60-70%）
- 混入前一难度区间的"长尾"成语（10-20%），保持连贯感
- 偶尔引入下一难度区间的"预览"成语（5-10%），制造新鲜感

### 4.2 难度分布示意

```
难度1-5   ████████████████████░░░░░░░░░░░░░░░░  ← 前500关主力
难度6-10  ░░░░░░████████████████████░░░░░░░░░░  ← 300-2000关主力
难度11-20 ░░░░░░░░░░░░░░████████████████████░░  ← 1500-4000关主力
难度21-30 ░░░░░░░░░░░░░░░░░░░░░░████████████░░  ← 3500-7000关主力
难度31-40 ░░░░░░░░░░░░░░░░░░░░░░░░░░░░████████  ← 6000-9000关主力
难度41-50 ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░████  ← 8500+关主力
三区混排  ████████████████████████████████████  ← Lv.20后（约7550关起）波浪中心+三区混排
          1    1000  2000  3000  4000  5000  6000+
                       关卡编号
```

### 4.3 选词规则

每关选词逻辑：
1. 计算基准难度 = ceil(关卡编号 / 200)
2. 主体选词：按 §3.1 条数分段，从基准难度±3 范围内随机选取
3. 长尾散落：按分段 0-2 条，从比基准低 5-10 的难度中随机选取
4. 预览混入：按分段 0-3 条，从比基准高 3-5 的难度中随机选取

### 4.4 示例

| 关卡/等级 | 成语构成 |
|-----------|----------|
| 第 1 关 | 主体 5 |
| 第 2 关 | 主体 6 |
| 第 3-4 关 | 主体 7 |
| 第 5 关 | 主体 8 |
| 6 关起、Lv.5 前 | 主体 8 + 长尾 0-1 + 预览 0-1 |
| Lv.5-9 | 主体 8 + 长尾 0-1 + 预览 1-2 |
| Lv.10-19 | 主体 7 + 长尾 1-2 + 预览 3 |
| Lv.20 后 | 主体 8 + 回顾 0 + 冲刺 2-3 + 惊喜 0-1 |

### 4.5 螺旋规则

- 难度 1 的成语在前 3000 关持续出现，占比逐渐降低
- 每个难度区间自然过渡，无断层
- 长尾成语保持游戏连贯感，避免"突然变难"

### 4.6 Lv.20 后：波浪中心 + 三区混排

- 难度中心：`center = round(30 + 10 × sin(关卡编号 / 150))`，限制在 20～40
- 主体（8 条）：`center ± 8`
- 回顾（0 条）
- 冲刺（2-3 条）：难度 `min(center+12, 46) ~ 50`
- 惊喜（0-1 条）：难度 `1-5` 或 `46-50`
- 每关总数控制在 10-12 条

### 5.4 积分与广告变现（2026-08-07 起，移除现实货币内购）

- 所有道具/装饰均以「积分」购买，不再使用真实货币
- 积分获取（积分最小单位为 1）：
  - 激励广告：每次完成 +3（商城「赚取积分」入口，带冷却）
  - 插页式激励广告：通关结算前 40% 概率提供观看选项，明确说明奖励并允许跳过；达到奖励条件后 +2，跳过、提前关闭或展示失败不奖励
  - 横幅广告：选择关卡 / 收藏 / 商城底部常驻，每累计观看 1 分钟 +1（每日上限 120 分，仅当前可见 Tab 累计）
- 激励广告频率：每天最多 100 次；前 10 次冷却 1 分钟，之后 90 次冷却 2 分钟
- 广告价值估算依据（2026 行业 eCPM 参考值，非 Google 官方保证）：

| 广告类型 | eCPM 参考（US） | 积分奖励 |
|----------|----------------|----------|
| 横幅 Banner | $1.2–$1.3 | 观看 1 分钟 +1 |
| 插页式激励 Rewarded Interstitial | — | 完成观看 +2 |
| 激励 Rewarded | $16–$20 | 每次 +3 |

- 合规说明：AdMob 未对激励广告设置硬性“每日次数”上限，但高频重复观看可能触发无效流量/滥用限制。当前实现 100 次/天 + 1/2 分钟冷却，建议在 AdMob 后台同时配置频次上限并持续监控；若从严合规，可将每日上限降至 30 次、冷却统一为 2 分钟
- 积分定价初值（估算结果确定前可调整）：
  - 提示卡 ×1：10 积分
  - 复活卡 ×1：15 积分
  - 备考礼盒（提示×3 + 复活×1）：40 积分
  - 广告兑换皮肤：1000–5000 积分（见 5.3）
  - 等级皮肤：仅等级奖励解锁，不可购买
- **不卖数值**：积分仅兑换道具/装饰，不影响关卡难度和成语选择

### 9.2 DistractorEngine

- 无修改，继续为每个空格生成干扰字

### 9.3 Database Schema

- 新增 `player_progress` 表：等级、经验、道具数量
- 新增 `collection` 表：已收藏成语
- 新增 `level_history` 表：通关记录
- 新增 `decoration` 表：装饰道具拥有状态
