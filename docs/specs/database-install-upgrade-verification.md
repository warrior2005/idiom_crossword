# 新安装、旧版本升级与资产说明

日期：2026-09-15。当前数据库结构版本12，四档内容版本5，主线策略版本3；三种版本号用途不同。

## assets/data 中的文件

| 文件 | 用途 | 是否仍需随包携带 |
|---|---|---|
| idiom_crossword.db | 新安装时复制为用户数据库；也提供相关字数据补齐来源 | 是 |
| four_tier_content.json | 累计内容补丁：29,724词的四档分类、来源、审核记录，以及222个新增词和字符索引所需资料 | 是，旧用户数据库不会直接被新资产覆盖 |
| mainline_content.json | 5处拼音修正；保留旧主线词池，供没有冻结候选盘且带support的旧题构建干扰字 | 是，目前仍有运行时引用 |

`four_tier_content.json` 按 `four_tier_version` 表判断是否需要更新，当前版本为5。补丁使用固定ID与成语双重校验，并在事务内更新；不修改用户的奖励、收藏、通关或存档。没有必要逐个执行内容版本1、2、3、4，旧内容可以直接应用累计版本5。

`mainline_content.json` 的拼音补丁按 `content_version` 表判断，当前为1。它的旧intro／foundation／expansion清单不再决定策略3的难度和词池；但游戏页为部分旧题重建候选盘时仍读取intro／foundation。新题已有冻结候选盘时直接使用存档，不走该分支。因此不能把这个JSON整体视为已废弃文件直接删除。

两个JSON在首次安装与每次启动时都会加载；已应用的内容版本会跳过更新事务。通常后续内容调整需要同时更新预置数据库、累计JSON和内容版本，保证新装与旧装最终数据一致。

## 实际启动顺序

1. 用户数据库不存在：复制随包数据库。存在同构数据库时继续使用原文件。
2. 应用拼音补丁、四档累计补丁，并按需补齐相关字数据。
3. Drift按结构版本执行缺少的表／列迁移，升至12。
4. 主线读取已有学习记录；旧冻结关卡仍恢复原题，新题使用策略3。

历史边界：如果旧数据库没有`idioms`表（早期为`idiom`单数表），现有启动逻辑会删除旧库并复制新资产。这条路径可以恢复启动，但不保留异构旧库的用户进度；本次没有更改此行为，不能称为无损迁移。
