# 逐档推进、复习数量与题目指纹

日期：2026-09-14。状态：整理最新产品规则及实现边界；数据完整审核已导入内容版本5，以下算法尚未落地。复习词的统计口径需要明确后才能决定选词约束。

## 1. 逐档推进

替换当前随内部step同时增加四档配额的做法。将“词汇推进阶段”与“词数、待填量、干扰量”等题面复杂度分开记录。

- 当前主体档为T时，最高只探索T+1，不能跳到T+2。
- 初始以入门为主体；达到较稳定的表现后，少量探索基础。
- 下一档从少量出现逐步成为主体。只有这一档有足够、分散到不同词的持续表现证据，才探索再高一档。
- 较低档可以少量、间歇出现；它们属于穿插或复习，不代表同时推进多个高档。
- 只卡一词不等同整个档位不会；多次提示和大量预填下完成的证据权重低于独立作答。
- 不要求做完某档全部词才能晋级，也不用总关号、年龄或旧1—50分驱动升档。
- 词汇组合每次只小幅变化，保留观察期，避免阶段切换引起骤变；局内冻结不变。

以6词题说明方向（仅示例，不是按关号固定的配置表）：

| 状态 | 示例 |
|---|---|
| 入门起步 | 6入门 |
| 试探基础 | 5入门＋1基础 |
| 基础成为主体 | 1入门＋5基础 |
| 试探拓展 | 1入门＋4基础＋1拓展 |
| 拓展成为主体 | 1基础＋5拓展，入门偶尔穿插 |
| 试探生僻 | 1基础＋4拓展＋1生僻 |

新阶段门槛需通过冷启动、强／弱基础、局部薄弱和长期稳定玩家轨迹确定，不能把短暂连胜直接等同掌握整档。当前三档同时加量及固定step22开始生僻的规则将被替换。

## 2. 复习词0—2个的口径

用户要求保留近期排除、随机选词和复习，并限制每题复习词数量。需要区分：

1. 主动安排的复习词：从到期／复习需求集合中计划选入0—2个，普通抽样仍可能出现更早见过的词。
2. 所有曾出现过的词：一旦见过，以后都占用每题最多2个名额。

二者对重复感的效果不同，不能用第一种名义悄悄放入大量旧词。第二种会与当前“熟悉词至少约半题”的预算直接冲突，而且稳定在有限词池内最终无题可出：例如入门现有475词，6词题每题至少4个全新词，仅靠该池最多支撑约百余题，然后必须允许更多旧词或停止该阶段。不能为了用完词池强行升档。

因此先明确口径及耗尽时规则，再实现数量约束；不能把“近期没出现”或“未熟练”冒充“从未出现”。在明确之前，不修改现有选词以猜测用户意图。

## 3. 成语集合hash

可以使用以下规范作为整组去重的唯一实现：

```text
canonical = sort(本关全部成语).join('|')
fingerprint = SHA-256(canonical)
```

成语顺序、布局、预填和候选字变化不改变指纹。因此同组词换布局也判作相同组合。指纹是整组去重的索引方式，不必另维护一套语义相同的去重逻辑；它不能识别只重复一半词的题。

建议持久保存实际展示过的新题指纹，涵盖完成、失败和换题。新题生成时检查，命中就重新取词／布局；恢复或重玩指定旧题直接加载冻结定义，不被当作新题阻止进入。已有历史题可据成语集合补算指纹。保存与新题接纳需处理一致性，避免并发生成重复组合；未展示的预生成候选不应算玩家见过。

用户此次选择保留现有近期排除和随机选词，暂不额外加入此前提出的近期20题半数重合硬限制，避免约束叠加。

## 4. 实施依赖

- 先明确复习口径，避免与熟悉度预算、档位可用量相矛盾。
- 新策略需单独版本化，统一修改各处策略识别与相邻题平滑记录，继续兼容内容版本2—5及旧冻结题。
- 档位推进和指纹检查必须进入候选生成及可行性评估，保留此前发现的剩余配额前瞻与有界搜索方向，不能只在最后反复拒绝完整题。
- 校准后6—12词、比例干扰且至少4个、答案消歧、奖励防重及每日挑战兼容继续作为硬边界。
