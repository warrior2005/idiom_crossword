# 成语分级与关卡体验改造方案

- 日期：2026-09-09
- 状态：P0—P2 首版代码已实施；初始词池与参数待目标玩家校准，发布效果待验证。
- 实现记录：[首版实现与验收](mainline_implementation_v1.md)；运行时抽样：[主线样本](mainline_samples_v1.md)。
- 核查基线：代码提交 `48edeb8`、当前随包数据库及评分 JSON。
- 目标：减少新手卡关，适配不同成语储备，避免后期主线依赖生僻词维持难度。
- 本文是本次改造的开发依据。与旧 PRD、成长设计、难度报告中的选词规则冲突时，以本文的目标和约束为准；旧文档保留为现状及历史背景。
- 本文中的关数、词数、配比是首轮实验建议，不是已验证的最优值；实施清单中的硬约束必须满足。

## 1. 核心决策

主线从“进度增加 → 生僻程度增加”调整为“在适合玩家的词汇范围内提供填字挑战，适量拓展并安排复习”。

1. 将成语准入、成语熟悉度、题面难度、个人掌握度分开处理。现有 `difficulty` 保留作兼容和辅助排序，不再单独决定主线选词。
2. 优先审核入门词池、约束最终生成结果，再逐步增加玩家适配；不等待全库重评分完成。
3. 科举等级保留成长奖励意义，与自动进入高难词池解耦。
4. 主线设置生僻度边界，后期通过题面、交叉组合、主题及复习提供变化；生僻词用于主动选择的挑战。
5. 保留现有交叉布局、消歧、进度及存档能力，分阶段改造，不重写整套引擎。
6. 成语内容升级必须覆盖老安装，保持已有成语 ID 及用户关系。

## 2. 已核实的问题与依据

### 2.1 分数是相对排序，不能直接代表新手熟悉度

[历史重平衡报告](idiom_difficulty_rebalance_report.md)记录的方案是：保持原始 LLM 分数桶的单调顺序，桶内按字符稀有度、释义等特征排序，再等量映射到 50 档。这个方法不能修复原始分数桶之间的错误，也不能测量不同人群的熟悉度。

当前随包库有 29,502 条成语，难度 1—4 共 2,142 条。各档已经不是完全等量，但仍接近历史分桶分布。当前数据库中的 `difficulty_original`、`difficulty_method`、`is_canonical` 非空记录均为 0；不能假设历史报告中的元数据已经进入当前资产。

实查样例（用于指出需要审核的差异，不作为自动改分指令）：

| 成语 | 当前 difficulty |
| --- | ---: |
| 守株待兔、画蛇添足 | 1 |
| 走头无路 | 1 |
| 走投无路 | 2 |
| 巷尾街头 | 3 |
| 蛊惑人心、鹤唳风声 | 4 |

[数据库构建脚本](../../scripts/build_database.py)从 `data/scoring_progress.json` 导入最终分数。本次运行 `python3 scripts/check_idiom_data.py`，数据库与数据源所有检查字段一致。字段一致不代表分级合理。常用成语约 1,000 条、低频词约几千到一万条等估计尚未验证，不得据此强制规定词池容量。

### 2.2 前 200 关没有细分的体验曲线

[spiral_difficulty.dart](../../lib/src/engine/spiral_difficulty.dart)：

- 第 1—200 关基准均为 1，主体范围均为 1—4；第 6 关起允许 4—6 分预览词。
- 前 5 关目标词数为 5、6、7、7、8；后续数量受科举等级影响，不根据实际卡关表现调整。
- [integrated_generator.dart](../../lib/src/engine/integrated_generator.dart)统一预填每个成语首字，后续再做消歧补字，缺少教学专用提示策略。
- [game_screen.dart](../../lib/src/ui/screens/game_screen.dart)传入固定 4×10 候选盘。[distractor_engine.dart](../../lib/src/engine/distractor_engine.dart)用总格数减答案数得到干扰数量，因此题目变小不一定减轻候选筛选负担。

### 2.3 混排数量没有约束最终成品

`IntegratedGenerator.generateSpiral` 将主体数量×6、长尾数量×8、预览数量×10 的候选合并，再按交叉及布局选词。配置“主体 8、预览 1”不保证最终只有 1 条预览词。主体与预览区间还可能重叠，未来配额必须使用明确且不重复计数的角色分配。

全局模式也先合并各区候选，再统一生成，存在相同问题。当前关卡质量比较主要考虑尺寸、形状平衡和交叉数，没有熟词配额或起手条件。螺旋生成失败后还会将主体范围放宽 ±2，新手边界可能被回退路径突破。

依据：[integrated_generator.dart](../../lib/src/engine/integrated_generator.dart)、[level_generation.dart](../../lib/src/state/level_generation.dart)。

### 2.4 后期有两条偏向难词的路径

科举等级 20 前仍使用按关数增长的螺旋规则，例如第 6,000 关主体范围为 27—33。科举等级达到 20 后，主线入口切换到全局模式，不是始终线性增长。

[global_difficulty.dart](../../lib/src/engine/global_difficulty.dart)中中心为 `30 + 10 * sin(levelNumber / 150)`，取整并限制在 20—40；复习数量实际为 0，冲刺区下限为 `min(center + 12, 46)`、上限为 50，惊喜区可能为 46—50。这里是候选区配置，不保证最终词数配额。

科举等级由经验累积产生，不等同于词汇能力。需要同时调整螺旋和全局路径，不能只把单条曲线放缓。入口涉及首页、关卡选择和游戏内下一关。

### 2.5 已允许复用，但没有个人复习闭环

`recentLevelExclusionCount = 3`，当前仅排除最近 3 关的主线用词，并未禁止长期重复。

[database.dart](../../lib/src/data/database.dart)已有整关耗时、提示、错误、填字次数和用词列表；自动收录及收藏不代表掌握。当前记录不能可靠区分某条成语的独立完成、提示后完成和延迟回忆。整关统计可支持初版粗粒度适配，但要补齐未完成和放弃记录，避免只观察通关玩家。

### 2.6 修改资产不会自动更新所有老用户

数据库通常首次安装才复制随包资产。同构旧库的现有升级逻辑中未发现成语难度的版本化同步；相关字补齐不能代替词库内容迁移。

`loadOrGenerateLevel` 优先恢复未完成存档，然后使用已通关冻结定义。修改生成器不会自动改变这些旧题。

[build_database.py](../../scripts/build_database.py)重建时按拼音排序递增分配 ID。新增、删词或修改拼音排序可能导致后续 ID 变化，不能直接将重建后的编号当作老用户内容更新依据。

## 3. 内容与数据设计

### 3.1 词库准入

将内容分为基础、拓展、挑战、待审四类用途；允许多个基础词集服务不同储备，不要求各类等量。

- 基础：经审核适合对应入门人群，优先规范常见表达。
- 拓展：规范且有学习价值，可在提示支持下进入主线。
- 挑战：低频词，进入玩家主动选择的挑战内容。
- 待审：来源、规范词形或熟悉度标签不可靠，暂不进入主线。

首批审核覆盖前 200 关可能入选的全部候选及回退路径，而不仅是种子词。参考教材和阅读材料覆盖、语料频率、规范词典及真实作答；AI 可辅助初筛，不作为唯一裁决。保存审核来源、置信度和内容版本。年龄或学段只作初始参考，不等同于能力。

旧 [difficulty-manual-change.md](../difficulty-manual-change.md) **仅参考第 4 部分修正 5 条错误拼音**：跌宕风流（4971）、改行自新（7158）、悬龟系鱼（24090）、抓耳搔腮（28904）、足尺加二（29284）。修正时同步检查 `pinyin_abbr`，并更新可重建的数据源、随包资产及老用户内容补丁，保持 ID 不变。

该旧文档其余内容，包括全库手工重评分、按每档抽样建立难度感觉及倒装词难度梳理，不作为本次开发要求；相关 CSV 也不作为必须执行的工作清单。难度和关卡改造统一以本文的最新分析为准。保持 ID 的要求来自本方案的用户数据兼容约束，不依赖旧文档。

字段名和存储结构在实施时按最小需求确定。已有空元数据列不能直接视为可信标签，也不要求本轮填满所有历史字段。

### 3.2 玩家与关卡信息

首版通过近期多关表现和可选偏好“轻松入门／日常挑战／成语高手”调整后续关卡；默认轻松入门。高手可以更快离开教学段，困难玩家得到更小棋盘和更多提示。无需先做独立考试。

后续每词记录至少应能区分：出现、独立完成、提示或查看答案后完成、错误、最后练习时间。交叉字自动补出的完成不应与完全独立回忆等同。P0/P1 的“基础词”只是经审核的熟悉度先验，不能声称玩家已掌握；个人熟词配额依赖后续记录。

关卡记录应带内容版本、生成策略版本、模式及实际题面配置，支持复现和分组分析。科举等级继续用于奖励，不作词汇能力字段。

## 4. 生成与体验约束

### 4.1 必须在最终关卡上验收

1. 每条成语符合当前模式准入；补词、重试和回退不得绕过。
2. 每条词明确归入本关一种配额角色；校验最终基础／复习／拓展数量，不能以候选池比例代替。
3. 限制拓展词数量，不只控制平均 difficulty。
4. 至少有明确起手点；通过题面和审核词汇保证玩家有合理入口。
5. 对预期需要支持的拓展词检查线索传播：暂时视为无法独立解出时，基础部分仍可推进，并能为它提供有效已知字。几何连通不等于认知可解。
6. 保留现有邻接、交叉、歧义和答案候选校验；增加已知字后仍保留实际作答内容。
7. 候选盘容量覆盖全部待填答案及所需重复字数量，干扰预算随题面调整。

认知可解性不能仅凭图算法证明。首版采用审核模板、基础词入口和可复现的线索传播规则进行近似检查，再用目标玩家试玩验证；不要将该代理检查描述为所有玩家必然能过关。

### 4.2 有边界的失败回退

在相同准入词池内重新采样或调整布局；仍失败时减小棋盘或使用审核模板。重试应有上限。不得为了提高生成成功率放入超出准入范围的词。强制验证回退后的最终成品。

缩小首关词数时，检查 `level_generation.dart` 中候选少于 5 条的提前返回等前置条件及相关测试，避免仅修改数量配置导致无法生成。

### 4.3 前 200 关首轮配置建议

| 阶段 | 目标 | 初始候选配置 |
| --- | --- | --- |
| 1—5 | 学会操作，获得连续成功 | 2—4 个基础词，更多已知字、更少候选字，明确起手点和教学提示 |
| 6—20 | 校准储备与操作负担 | 逐步到 4—6 个词，单关最多 1 个拓展词，可为 0 |
| 21—50 | 建立舒适区 | 稳定规模，开始复习，改变交叉结构 |
| 51—200 | 保持变化与学习 | 基础挑战、拓展、复习交替，根据表现选择配置 |

配置需要抽样生成和目标玩家试玩后确定。每次不要同时提高词数、生僻度、挖空量和干扰强度。不要只根据耗时调整；停留、输入速度和中断并不等于储备不足。采用多关观察、小幅调整并保持一段稳定体验，避免答得快就立即升难。

### 4.4 后期与复习

主线不再随着关数无限提高生僻度。通过熟悉成语的新交叉组合、挖空位置、主题、易混辨析和复习提供变化。可选挑战承担生僻词探索。

个人记录成熟后，可以实验“约 70% 已掌握、20% 待巩固、10% 新词”，但不得机械套用：小棋盘按实际词数处理，新玩家没有足够掌握记录时使用基础词先验及更强提示；新词比例不是必须凑满的最低值。

复习使用变化后的题面并区分提示后完成与延迟独立完成。已有最近 3 关排除可作为避免重复疲劳的默认规则，若复习需要例外，应显式设计和测试，而不是无意绕过。


### 4.5 候选字数量随词数与题面难度调整

当前调用固定为 4 行、每行 10 字，共 40 个候选字。后续将候选字数量作为独立的题面难度参数，适用于整个主线，不只用于缩小教学关。

- 根据本关词数、交叉及已知字处理后的实际待填格数，以及目标题面难度确定候选总数。不能简单按“成语数×4”估计答案数量。
- 候选总数 = 实际待填答案数量（保留重复字份数）+ 干扰字预算。少词、轻松配置减少干扰；需要更多挑战时可适量增加干扰，但不随关数或旧 `difficulty` 分数机械增加。
- 候选数量与形近／音近干扰强度分别配置；提高词汇挑战时，不应无意同时提高全部题面负担。
- 不再将 4×10 作为固定总量要求。行数及每行数量的具体布局按屏幕宽度和点击尺寸确定；若保留每行 10 个，应支持改变行数或末行不足 10 个，不能为了补满矩形强行添加超预算干扰字。
- 保持答案槽位及重复字份数正确，覆盖填入、清除、提示、重玩和断点恢复。候选布局在进入关卡时确定，不在玩家作答过程中随意增删或重排。
- 精确数量区间和干扰比例通过样本、移动端布局检查及试玩确定，本方案不预设一张未经验证的固定数量表。

## 5. 老用户迁移与共享题目

1. 内容版本与数据库 schema 版本分开。通过可重复执行的事务增量更新审核标签、分数及必要内容，不覆盖用户表。
2. 保持现有成语 ID。构建数据和发布差异时显式检查 ID 稳定性；新增词采用稳定映射，停用词不能破坏历史引用。
3. 新安装与旧安装更新后，对同一内容版本得到一致的可选词和标签；更新中断不留下部分版本，重试不重复破坏数据。
4. 新生成题使用新策略。未完成存档继续恢复，提供玩家明确触发的“换一道”来处理旧题卡关；换题时同步处理本题作答状态，避免重复奖励或自动记为通关。
5. 已通关冻结题保留，历史奖励、收藏和进度不丢失。旧存档缺少新增字段时必须兼容。
6. 每日挑战及其他共享题不随个人能力动态变题。当前确定性由日期种子与候选数据共同决定，修改词库也可能改变同日题；实施内容更新时必须定义同一期内容／策略版本的一致性边界，不能只依赖相同 seed 宣称跨版本全服同题。
7. 上线方案应能回退生成策略；内容更新不得依赖删除整个用户数据库。具体开关机制按现有架构选择，不预设新增远程配置系统。

## 6. 开发拆分与完成条件

### P0：内容底线、生成硬约束和内容更新

- [ ] 建立入门准入词集，完成首批审核，保存依据与版本，打通源数据到资产的构建链。
- [ ] 仅参考旧手工文档第 4 部分修正 5 条拼音及对应缩写，纳入源数据、资产和老用户内容更新。
- [ ] 在最终布局校验配额和准入，处理重叠角色、重试和失败回退；补充可起手模板或规则。
- [ ] 完成稳定 ID 的内容增量更新及新旧安装一致性验证。
- [ ] 实现旧题主动换题路径，保留已完成冻结题和用户数据。

完成条件：正式生成路径和所有回退路径都不能产出不符合准入的入门词；最终拓展数量受限；旧安装获得相同内容规则且用户数据不丢失。

### P1：前期题面和主线难度规则

- [ ] 前 20 关支持较小棋盘和教学已知字；整个主线支持候选字数量随词数、实际待填格数及题面难度调整，统一更新生成前置条件、候选布局及恢复逻辑。
- [ ] 解除科举等级 20 与高难词池切换绑定；同时对原螺旋和全局路径落实主线生僻度边界。
- [ ] 覆盖首页、关卡选择、下一关入口；保持每日挑战独立策略。
- [ ] 在发布前补齐卡住、放弃、提示和配置版本等观测，建立旧版基线。

完成条件：候选总数符合本关答案数量与干扰预算，不再固定 40 格；教学配置不会产生过量干扰；高关数及高科举等级不会绕过主线准入；相同模式下不同入口规则一致。

### P2：前 200 关适配与定向复习

- [ ] 增加可选储备偏好，基于近期多关表现做小幅、稳定调整。
- [ ] 记录每词练习和提示使用，接入定向复习。
- [ ] 补齐第 21—200 关的变化及节奏，支持高手较快离开入门段。
- [ ] 数据足够后再评估更细的个人成功概率模型，不作为前两阶段依赖。

完成条件：适配不只依赖通关样本、年龄、耗时或科举等级；提示完成不直接计为掌握；玩家调整与复习路径可复现、可解释。

## 7. 验证与发布评估

### 自动化及人工质量验证

复用 [level_quality_test.dart](../../test/engine/level_quality_test.dart) 和 [level_samples_report.dart](../../tool/level_samples_report.dart)，但扩展覆盖运行时的候选查询、分区、回退和最终成品，而不只直接调用引擎。当前报告及质量测试读取评分 JSON，不能代替资产标签、内容迁移和实际入口的验证。

- 选择固定种子覆盖第 1、5、6、20、21、50、51、200、201、6,000、10,001 关，以及科举等级切换边界。
- 验证准入、最终配额、起手路径、不同词数及题面难度下的候选总数、末行不足整行、重复答案字和消歧；覆盖可变候选盘的填入、清除、提示及断点恢复。
- 覆盖词池稀疏、角色区间重叠、排除最近词、生成失败和审核模板回退。
- 统计生成成功率、耗时、回退率、词数、待填格数、候选数、拓展词数量与最高词汇等级；报告极端样本，不只报告平均分。
- 用旧库和旧存档验证内容更新、ID、收藏、奖励、冻结题、升级中断重试及换题。
- 人工审核代表样本，并邀请不同储备的玩家试玩前 20 关。几何合法和测试通过不能替代体验验证。

### 产品指标

核心观察首 10 关流失、前 200 关分段完成、次日／七日留存；同时观察无提示完成、连续卡关、提示依赖，以及条件具备后的新词延迟独立答对率。

事件至少能关联关卡实例、模式、内容／策略版本、初始偏好、实际题面、进入、提示、完成、失败和退出／恢复。退出或中断不直接判为不会；整关耗时需处理非活跃时间。先建立观测口径，再设置改善幅度目标，不虚构基线或承诺留存提升。

有实验分流能力时采用用户级稳定分组并保持版本可追踪；否则先进行分批发布和同口径对比，明确其因果判断限制。不要仅凭通关率上涨判成功，也不要用后期幸存玩家的答对率代表全部玩家熟悉度。
